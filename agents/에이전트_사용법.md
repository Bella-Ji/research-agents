# .claude/agents 사용법

이 파일은 이 폴더(`agents/`, 파이썬 레거시 시스템)에 있지만, 설명하는 대상은
**`.claude/agents/` + `.claude/commands/`** (Claude Code 네이티브 서브에이전트 10개)이다.
실제 코드/정의는 이 폴더가 아니라 `.claude/`(숨김 폴더)에 있으니, 수정할 때는 거기로 갈 것.

---

## 1. 구조 한눈에 보기

```
자연어 or 슬래시 커맨드   ← 서현님이 입력하는 곳
        ↓
서브에이전트 (.claude/agents/*.md)   ← 실제 작업 수행
        ↓
context 파일 (.claude/context/*.md)   ← 이론·변인 SSOT, 모든 에이전트가 참조
```

슬래시 커맨드를 몰라도 된다 — 자연어로 말하면 CLAUDE.md의 트리거 표를 보고 맞는 커맨드로 라우팅된다.

---

## 2. 자연어 트리거 → 슬래시 커맨드

| 이렇게 말하면 | 실행되는 커맨드 |
|---|---|
| "이 논문 요약해줘", "PDF 요약" | `/summarize-pdf` |
| "갭 찾아줘", "연구 갭", "gap 분석" | `/find-gaps` |
| "관련 논문 찾아줘", "문헌 탐색", "vault 검색" | `/search-lit` |
| "인용 검사", "APA 형식", "citation 확인" | `/check-citations` |
| "초안 검토", "draft 검토", "논문 피드백" | `/review-draft` |
| "글쓰기 코칭", "논리 분석", "writing coach" | `/coach-writing` |
| "논문 구조", "아웃라인", "챕터 구성" | `/outline-dissertation` |

`/peer-review`, `/check-flow`, `/update-structure`는 트리거 표에 없음 — 이름으로 직접 불러야 함.

---

## 3. 에이전트별 사용법

### 문헌 탐색

| 에이전트 | 부르는 법 | 인풋 | 아웃풋 |
|---|---|---|---|
| `pdf-summarizer` | `/summarize-pdf "PDF경로"` (단일) / `/summarize-pdf --batch` (WM 폴더 전체 미처리 PDF) | PDF 경로 | PDF와 같은 폴더에 `{파일명}_요약.md` |
| `lit-searcher` | `/search-lit "키워드"` | 키워드 (예: `cor`, `부당대우 회복`) | 파일 저장 없음, 채팅에 합성 답변만 |
| `gap-explorer` → `gap-synthesizer` → `gap-strategist` | `/find-gaps [PDF폴더]` (생략 시 `02. reference/phd/` 전체, `--force`로 재처리) | PDF 폴더 | ①논문별 `*_갭분석.md` → ②`gap_landscape_*.md` → ③`gap_strategy_*.md` (연구 모형 제안, 전부 `gap_synthesis/`에 저장). **3단계가 한 번의 커맨드로 자동 체이닝됨** — 따로따로 부를 필요 없음 |

### 인용 검사

`citation-checker` → `/check-citations "파일|폴더경로" [--ref 참고문헌.md] [--save]`
APA 7판 형식 오류를 심각도별로 정리 + 수정안. `--ref`로 참고문헌 목록과 교차검사 가능, `--save`로 결과를 파일로 저장.

### 글쓰기 검토 — 셋의 판단 기준이 다름 (헷갈리는 지점)

| 에이전트 | 보는 것 | 비교 대상 | 부르는 법 |
|---|---|---|---|
| `draft-reviewer` | 이론 정합성(JD-R/COR)·인용이 주장을 뒷받침하는지·학술 어조 | research-profile.md의 규칙 | `/review-draft "초안경로" [섹션명]` → `*_review_YYYYMMDD.md` |
| `coach-writing` | 논리 *전개 방식*(순서·전환). 내용의 옳고 그름은 안 봄 | 우수 논문(exemplar) | `/coach-writing --analyze "PDF경로" [--sections ...]` (1편 비교) \| `--multi [섹션키]` (good_papers 전체 종합) \| `--revise 섹션키` (문단 직접 수정) |
| `peer-reviewer` | 논문 전체가 게재/졸업 가능한 수준인지 — 기여도·방법-결과 정합성·과대해석·대안설명·한계충분성 (5축) | 저널 심사 기준 | `/peer-review "논문경로" [dissertation\|journal-article] [Pass번호]` — **2-Pass**: Pass 1(컨텍스트 수립) 결과를 보고 승인해야 Pass 2(상세 리뷰)가 진행됨. 전에 `*_요약.md`/`*_갭분석.md`가 부족하면 `/find-gaps`·`/search-lit`을 먼저 돌릴 것 (peer-reviewer는 실시간 재검색 안 함) |

**헷갈리면**: 비교 대상이 다른 논문이면 `coach-writing`, 비교 대상이 규칙/이론이면 `draft-reviewer`, 논문 전체의 설득력을 보고 싶으면 `peer-reviewer`.

셋 다 원본 파일은 수정하지 않고 별도 리포트 파일만 생성한다.

### 구조

`structure-architect` 하나가 3개 커맨드를 담당:

| 커맨드 | 하는 일 |
|---|---|
| `/outline-dissertation` | STRUCTURE.md 없으면 생성. 연구 개수·핵심 질문을 확인받고 서론 8단계·연구별 4섹션·종합논의를 claim 수준까지 채운 아웃라인 작성 |
| `/check-flow` | STRUCTURE.md + 현재 초고를 읽고 가설-이론-결과-논의 매핑, 논리 흐름 6항목 점검 → 통과/문제 항목 보고. "논리가 딴 데로 새는지" 체크할 때 이거 |
| `/update-structure` | 집필 진행 상황을 STRUCTURE.md status에 반영, diff 요약 + 다음 작성 우선순위 제안 |

## 4. 주의사항

- 초안/원본 논문 파일은 어떤 에이전트도 직접 수정하지 않음 — 전부 별도 리포트 파일 생성
- `/find-gaps`는 학위논문(파일명에 박사/석사/thesis)은 자동 fallback 처리, 방법론 개관 논문은 갭이 안 나오는 게 정상
- `.gap_exploration_history.json`은 `run.py`(파이썬 레거시) 전용 — 건드리지 않음
- 파이썬 `run.py` 명령들(`python3 run.py pdf/gap/synth/strategy/writing/cite/search`)은 위 커맨드들과 병행 유지 중이며 서로 출력 형식이 같도록 맞춰져 있음. 둘 중 하나만 써도 됨 — 지금은 `.claude/` 쪽이 최신
